# ✈️ 새로운 여행지 추가 가이드 (add-destination)

이 문서는 트립파인더 웹서비스에 새로운 여행지(국내/해외)를 안전하고 일관된 형식으로 추가하기 위한 표준 작업 절차입니다. 초보자도 쉽게 따라 할 수 있도록 7단계 순서로 구성되어 있습니다.

---

## 📌 작업 단계 요약

```text
[1. 데이터 구조 확인] ➔ [2. 여행지 데이터 작성] ➔ [3. 이미지 URL 등록] ➔ [4. 추천 조건 설정] ➔ [5. UI 표시 확인] ➔ [6. 모바일 레이아웃 확인] ➔ [7. 린트 및 빌드 검증]
```

---

## 1단계: 기존 여행지 데이터 구조 확인

여행지 데이터를 추가하기 전에 먼저 TypeScript 인터페이스 정의와 기존 샘플 데이터를 확인합니다.

* **인터페이스 정의 파일**: `src/types/travel.ts` (`Destination` 인터페이스)
* **데이터 저장소 파일**: `src/data/destinations.ts` (`MOCK_DESTINATIONS` 배열)

### 필수 필드 목록 (`Destination`)
* `id` (string): 고유 식별자 (영문 소문자, 예: `'sapporo'`, `'rome'`)
* `name` (string): 여행지 이름 (예: `'삿포로'`, `'로마'`)
* `country` (string): 국가명 (예: `'일본'`, `'이탈리아'`, `'대한민국'`)
* `region` (string): 대륙 및 지역 (예: `'아시아 / 일본 홋카이도'`, `'유럽 / 이탈리아'`)
* `badge` (string, 선택): 카드 상단 강조 배지 (예: `'설경 & 미식의 성지'`)
* `imageUrl` (string): 고화질 대표 이미지 URL (Unsplash 등)
* `summary` (string): 1~2줄 요약 설명 (카드용)
* `description` (string): 상세 소개글 (모달용)
* `suitableStyles` (TravelStyle[]): 적합한 스타일 (`'휴양'`, `'맛집'`, `'관광'`, `'자연'`, `'액티비티'`)
* `suitableCompanions` (CompanionType[]): 추천 동행자 (`'혼자'`, `'친구'`, `'연인'`, `'가족'`)
* `suitableDurations` (TravelDuration[]): 추천 기간 (`'2박 3일'`, `'3박 4일'`, `'4박 5일'`, `'5박 이상'`)
* `budgetLevel` (TravelBudget): 예산 분류 (`'50만원 이하'`, `'100만원 이하'`, `'150만원 이하'`, `'150만원 초과'`)
* `estimatedCostPerPerson` (string): 1인 예상 경비 텍스트 (예: `'약 60만 ~ 90만원 (항공/호텔/식비)'`)
* `flightTimeOrDistance` (string): 이동/소요 시간 (예: `'비행기 2시간 40분 (직항)'`)
* `bestSeason` (string): 최적 여행 시기 (예: `'12월 ~ 2월 (눈꽃 축제)'`)
* `highlightTags` (string[]): 해시태그 3~5개 (예: `['#눈꽃축제', '#스프카레', '#오타루운하']`)
* `whyRecommendedReasons`: 맞춤 추천 사유 템플릿
* `sampleItinerary` (DayPlan[]): 일자별 추천 코스 (Day 1, Day 2, Day 3 등)
* `mustEat` (string[]): 필수 추천 음식 3~4개
* `travelTips` (string[]): 현지 여행 꿀팁 2개 이상

---

## 3단계: 필요한 이미지 정보 추가

* **이미지 출처**: 저작권에 문제가 없는 **Unsplash** 여행 사진 권장
* **URL 포맷**: 끝에 `?auto=format&fit=crop&w=1200&q=80` 파라미터를 붙여 최적화
* **사진 기준**:
  * 해당 여행지의 대표 랜드마크나 분위기가 뚜렷하게 드러나는 고해상도 가로형 사진
  * 과도한 텍스트나 워터마크가 없는 깨끗한 이미지

---

## 4단계: 추천 조건 (스코어링) 설정

사용자가 설문에서 선택한 조건과 여행지가 매칭되도록 아래 4개 요소를 정확히 설정합니다.

1. **`suitableStyles`**: 5가지 스타일 중 2~4개 선택 (`'휴양'`, `'맛집'`, `'관광'`, `'자연'`, `'액티비티'`)
2. **`suitableDurations`**: 적합한 일정 범위 선택 (`'2박 3일'`, `'3박 4일'`, `'4박 5일'`, `'5박 이상'`)
3. **`budgetLevel`**: 대표 예산 구간 1개 선택 (`'50만원 이하'`, `'100만원 이하'`, `'150만원 이하'`, `'150만원 초과'`)
4. **`suitableCompanions`**: 분위기가 잘 맞는 동행자 선택 (`'혼자'`, `'친구'`, `'연인'`, `'가족'`)

> [!TIP]
> `whyRecommendedReasons` 내 `style`과 `companion` 속성에 사용자가 선택한 스타일에 부합하는 자연스러운 한국어 문장을 반드시 작성해 주세요. 추천 결과 화면에서 개인 맞춤형 문구로 표시됩니다.

---

## 5단계: UI에서 정상적으로 표시되는지 확인

새 여행지가 웹 화면에서 정상적으로 렌더링되는지 확인합니다.

1. **메인 홈 화면 (추천 대기 중인 대표 여행지 섹션)**:
   * 메인 히어로 하단의 '추천 대기 중인 대표 여행지' 갤러리에 추가한 여행지(이름, 지역, 배지, 태그, 이미지)가 자동으로 카드로 렌더링되는지 확인
   * 상단 카운트(`국내외 N대 대표 명소 분석`) 숫자가 자동 증가했는지 확인
2. **설문 진행 후 결과 화면**:
   * 새로 추가한 여행지의 조건(예: 플로리다 - [휴양, 액티비티], 4박 5일, 150만원 초과, 가족)을 선택하여 추천 실행
   * Top 3 카드에 이미지, 매칭률 점수, 배지, 추천 이유, 1인 경비가 정상 출력되는지 확인
3. **상세 모달**:
   * 카드를 클릭했을 때 상세 팝업이 뜨며 일자별 코스, 대표 음식, 여행 꿀팁이 깔끔하게 표시되는지 확인

## 6단계: 모바일 레이아웃 확인

* 개발자 도구(F12) 디바이스 툴바를 켜고 모바일 뷰포트(360px ~ 430px)로 전환합니다.
* 점검 항목:
  * [ ] 여행지 이름이나 태그가 모바일 화면 밖으로 넘치거나 깨지지 않는가?
  * [ ] 카드 내 버튼 터치 영역이 충분한가 (`min-h-[44px]`)?
  * [ ] 상세 모달 스크롤이 매끄럽고 닫기 버튼(`X`)이 터치하기 쉬운 위치에 있는가?

---

## 7단계: 린트 및 프로덕션 빌드 검증

작업 완료 후 터미널에서 다음 명령어를 실행하여 0 에러를 확인합니다.

```bash
# 1. 린트 검사
npm run lint

# 2. 프로덕션 빌드 검사 (TypeScript 컴파일 & 번들링)
npm run build
```

빌드가 성공하면 깃허브에 변경사항을 커밋 & 푸시합니다:
```bash
git add src/data/destinations.ts
git commit -m "feat: add new destination [여행지 이름]"
git push origin main
```
